# แก้ตำแหน่งผ่าน Google Sheet

Google Sheet เป็น **ที่แก้ตำแหน่งที่เดียว** — ส่งค่าเข้าระบบทางเดียว (ชีต → Supabase)
PDA และหน้าเว็บอ่านจาก Supabase เหมือนเดิม ไม่ต้อง build APK ใหม่

```
พนักงานแก้คอลัมน์ ตำแหน่ง / หมายเหตุ ในชีต
  ├─ ทันทีที่แก้ (onEditInstallable) → ส่งเฉพาะแถวที่แก้ → anin_loc.sheet_apply()
  └─ ทุก 10 นาที (reconcile)        → ส่งทั้งชีต เก็บตกสิ่งที่ onEdit ไม่เห็น
                                       (sort / ลบแถว / onEdit ล้ม / มีคนแก้ DB ตรง)
anin_loc.sheet_apply() → item_locations → trigger เขียน location_history (source = 'sheet')
```

| ไฟล์ | คืออะไร |
|---|---|
| `Code.gs` | สคริปต์ทั้งหมด — **ต้นฉบับอยู่ที่นี่** แก้แล้ววางทับใน Apps Script editor |
| `appsscript.json` | manifest (timezone + สิทธิ์ที่ขอ) |
| `../supabase/migrations/0006_sheet_sync.sql` | ฟังก์ชัน `sheet_apply` ฝั่ง DB |

---

## ติดตั้ง (ครั้งเดียว)

1. **รัน `0006_sheet_sync.sql`** ใน Supabase SQL Editor
2. **ใช้บัญชีกลางของแผนก** สร้าง Google Sheet ใหม่ (ว่าง)
   การซิงก์อัตโนมัติทำงานในนามบัญชีที่ติดตั้ง — บัญชีส่วนตัวถูกปิดเมื่อไหร่ ซิงก์หยุดทันที
3. ในชีต: **Extensions → Apps Script**
4. **Project Settings (⚙️) → ติ๊ก "Show appsscript.json manifest file in editor"**
5. กลับไปหน้า Editor
   - วาง `Code.gs` ทับไฟล์ `Code.gs`
   - วาง `appsscript.json` ทับไฟล์ `appsscript.json`
   - กด Save
6. **Project Settings → Script Properties → Add script property**
   - `SUPABASE_ANON_KEY` = ค่าเดียวกับ `VITE_SUPABASE_ANON_KEY` ใน `.env`

   > ⚠️ **ห้ามใส่ `SUPABASE_SERVICE_KEY` เด็ดขาด** — key นั้นเข้าถึงฐาน POS (`public`) ได้ทุกตาราง
   > และทุกคนที่เปิด Apps Script ได้จะเห็นค่านี้ สคริปต์จะปฏิเสธถ้าเจอ service key
   > (ถ้าเผลอใส่ไปแล้ว ให้หมุน service key ใหม่ที่ Supabase)

   `SUPABASE_URL` ไม่ต้องใส่ — ใช้ค่าในโค้ด ใส่เฉพาะตอนย้ายโปรเจกต์
7. กลับไปที่ชีต → รีเฟรชหน้า → เมนู **📦 ตำแหน่ง → ตั้งค่าครั้งแรก**
   - ครั้งแรกจะขอสิทธิ์ และขึ้นว่า "Google hasn't verified this app"
     → **Advanced → Go to … (unsafe)** เป็นเรื่องปกติของสคริปต์ภายใน
   - ดึงสินค้าทั้งหมด (~8,000 แถว) ใช้เวลาประมาณ 1 นาที
8. **Share → ให้สิทธิ์ Editor** กับพนักงานที่ต้องแก้ตำแหน่ง
9. **Vercel → Settings → Environment Variables** → `VITE_LOCATION_SHEET_URL` = ลิงก์ชีต → Redeploy
   ปุ่มแก้ตำแหน่งในเว็บและ PDA จะหายไป บน desktop มีลิงก์มาที่ชีตแทน

## เมนู 📦 ตำแหน่ง

| เมนู | ใช้เมื่อ |
|---|---|
| **ซิงก์ทั้งหมดตอนนี้** | ซิงก์อัตโนมัติหยุดเพราะเกินเพดาน หรือตั้งใจแก้หลายร้อยแถวพร้อมกัน — แสดงจำนวนให้ยืนยันก่อนเขียน |
| **อัปเดตจากระบบ** | หลัง `npm run import` มีสินค้าใหม่ · หรือมีคนลบแถวในชีตไป (เติมกลับพร้อมตำแหน่งเดิม) · อัปเดต dropdown |
| ตั้งค่าครั้งแรก | ทำได้ครั้งเดียวตอนแท็บยังว่าง — มีข้อมูลแล้วจะไม่เขียนทับ |
| ติดตั้งการซิงก์อัตโนมัติใหม่ | เปลี่ยนบัญชีที่รันการซิงก์ — **ให้ติดตั้งคนเดียว** |

## เพดานความปลอดภัย

กันพลาดที่เกิดง่ายในสเปรดชีต เช่น เลือกทั้งคอลัมน์แล้วกด Delete หรือเรียงข้อมูลแค่คอลัมน์ตำแหน่ง
(ตำแหน่งจะสลับไปผูกกับสินค้าผิดตัวทั้งไฟล์)

| | เพดาน | เกินแล้วเกิดอะไร |
|---|---|---|
| แก้ในชีตครั้งเดียว (วาง/ลบหลายช่อง) | 200 รายการ | ไม่บันทึก · คอลัมน์สถานะขึ้น ⏸ · แท็บ "บันทึกซิงก์" เป็นสีแดง |
| ซิงก์อัตโนมัติ | 50 รายการ | ไม่บันทึก · แท็บ "บันทึกซิงก์" เป็นสีแดง |

ถ้าไม่ได้ตั้งใจ → กด Ctrl+Z · ถ้าตั้งใจ → เมนู **ซิงก์ทั้งหมดตอนนี้**
ปรับเพดานได้ที่ `EDIT_MAX_CHANGES` / `RECONCILE_MAX_CHANGES` ต้นไฟล์ `Code.gs`

## สำหรับพนักงาน (ส่งต่อได้)

- แก้ได้เฉพาะคอลัมน์ **ตำแหน่ง** และ **หมายเหตุ** (หัวคอลัมน์สีเหลือง) — บันทึกทันทีที่กด Enter
- **ดูคอลัมน์สถานะทุกครั้ง** — ถ้าขึ้น ℹ️ ทั้งที่ตั้งใจพิมพ์รหัสชั้นวาง แปลว่าพิมพ์ผิด
- วางค่าจากที่อื่นให้ใช้ **Ctrl+Shift+V** (วางเฉพาะค่า) — Ctrl+V ธรรมดาจะเอา format ต้นทางมาด้วย
- กรอง/เรียงข้อมูลให้ใช้ **Data → Create a filter view** — ไม่กระทบคนอื่น
  **ห้ามเรียงข้อมูลแค่คอลัมน์เดียว**
- ลบตำแหน่ง = ล้างช่องตำแหน่ง · **อย่าลบทั้งแถว**

## ข้อจำกัด

- **ชื่อคนแก้:** จะได้อีเมลก็ต่อเมื่อทุกคนใช้บัญชี Google Workspace โดเมนเดียวกับเจ้าของสคริปต์
  ถ้าไม่ใช่ ประวัติจะบันทึกว่า `google-sheet` แต่ยังดูรายเซลล์ได้ที่ File → Version history ของชีต
- **เมื่อชีตเป็นที่แก้ที่เดียวแล้ว ห้ามรัน `npm run import:locations`** และห้ามแก้ตำแหน่งใน DB ตรงๆ
  การซิงก์อัตโนมัติจะเขียนค่าจากชีตทับกลับ (หรือถ้าต่างกันเยอะจะหยุดแล้วแจ้งเตือน)
- **โควตา Apps Script:** บัญชี Gmail ทั่วไปรัน trigger ได้รวม 90 นาทีต่อวัน · Workspace 6 ชั่วโมงต่อวัน
  ซิงก์ทุก 10 นาทีใช้ไม่กี่วินาทีต่อรอบ จึงไม่ถึงโควตา
- trigger ที่คนอื่นติดตั้งไว้ ลบจากเมนูของเราไม่ได้ (Apps Script เห็นแค่ trigger ของบัญชีตัวเอง)

## ปิดโหมดชีต (กลับไปแก้ในเว็บ)

1. ลบ `VITE_LOCATION_SHEET_URL` ใน Vercel → Redeploy
2. **Apps Script → Triggers (⏰) → ลบ `onEditInstallable` และ `reconcile`**
   ถ้าไม่ลบ ซิงก์อัตโนมัติจะเขียนค่าในชีตทับสิ่งที่แก้ในเว็บ
